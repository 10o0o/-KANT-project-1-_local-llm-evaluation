# llama.cpp 기록 복구 가능성 점검

2026-09-16 AI의 코드 조회 결과를 참고했다. 이번 작업은 가능성 점검이며 기록 코드를 구현하거나 모델·채점을 실행하지 않았다.

과거 코드는 `pre-cleanup-2026-09-15` 태그의 `src/llm_eval/local_chat.py`와 `utils.py`에 있다. 조회 방법은 [정리 이력](history/README.md)을 따른다. 현재 호출은 `src/llm_eval/llama_cpp.py`, 결과 저장은 `src/llm_eval/benchmark/runner.py`에 있다.

| 항목 | 확인 결과와 복구 방향 |
| --- | --- |
| 전체 응답 시간 | 과거 호출 전후 `perf_counter()` 패턴 재사용 가능. 성공·예외 양쪽에서 경과 시간을 기록한다. 서버 내부 생성 시간과 구분한다. |
| 실제 입력 | 호출 시점의 prompt를 보존할 수 있다. 현재 결과에는 정확한 요청 프롬프트가 저장되지 않는다. |
| 호출 실패 | 현재 chat 예외는 결과 저장 전에 발생한다. 과거 예외 기록의 단계·오류 유형·경과 시간·요청 설정 구조를 재사용할 수 있다. 실패 원본 보존과 재시도 처리는 구현할 때 함께 확인한다. |
| 입력 처리·생성 시간/속도 | 응답 raw timings는 이미 저장한다. `prompt_ms`, `prompt_per_second`, `predicted_ms`, `predicted_per_second`를 현재 단위에 맞춰 연결할 수 있다. Ollama의 나노초 필드와 혼용하지 않는다. |
| 채점 기록 | WA·TLE·RE 등과 테스트별 실행 시간은 이미 저장한다. 기존 Judge 기록을 유지한다. |
| 모델 로딩 시간 | 현재 OpenAI 호환 응답에는 Ollama load_duration에 대응하는 값이 없다. 서버 시작 계측 등 별도 방법이 필요하며 요청 전체 시간으로 대체하지 않는다. |
| VRAM | Ollama client.ps().size_vram 조회는 재사용할 수 없다. 서버 프로세스·장치 관측 등 별도 방법과 출처·관측 시점을 정해야 한다. 전체 GPU 메모리를 모델별 값으로 부르거나 관측 한 번을 최고값으로 부르지 않는다. |
| 워밍업 | 현재 실행기에는 명시적 워밍업 기록이 없다. 모델당 1회와 본 실험 제외 원칙에 맞춰 직접 준비해야 한다. |

미측정은 null과 사유로 남기고 실제 0과 구분한다. 생성 시간 0 이하 또는 필드 누락이면 속도를 계산하지 않는다. 지표별 평균에는 유효 건수 n을 표시한다. 이 문서는 본 실험 준비 완료의 근거가 아니다.
