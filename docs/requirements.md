## 사용 사례

개인 알고리즘 학습용으로, 문제 설명에서 접근법·정당성·시간/공간 복잡도 설명과 실행 가능한 Python 정답 코드를 얻는다. 정답 코드를 우선한다. 그림 없이 텍스트만으로 해결 가능한 문제로 범위를 한정하며 그림을 봐야 풀 수 있는 문제는 제외한다.

아래는 발제 공통 기준과 구분한 사용자 정의 기준이다. License는 개인 이용 조건과 준수사항을 확인하며 상업적 이용 가능 여부는 필수 통과 조건으로 두지 않는다. 현재 장비에서의 실행 가능성·입출력 길이 수용·License 조건의 실제 충족 여부는 별도로 확인한다.

## 난이도 범위

문제 난이도는 본인의 체감을 기준으로 1~10으로 구분한다. 외부 사이트의 공식 난이도를 환산한 척도는 아니며, 다음 세 수준을 기준점으로 삼는다.

- **1:** AtCoder ABC 초반~중반 문제 수준
- **5:** AtCoder ABC 중반~후반 문제 수준
- **10:** Codeforces Div.1 후반 문제처럼 FFT, 금광 세그먼트 트리 등의 고급 기법이나 깊은 수학적 지식, 게임 이론, 어려운 애드혹 발상이 필요한 수준

나머지 난이도는 이 기준점 사이에 체감에 따라 배치하고, 각 문제에 난이도를 부여한 이유를 짧게 기록한다. 특정 알고리즘의 사용 여부만으로 난이도를 결정하지 않는다.

# 제출 규칙

- 최초 생성 코드를 로직 수정 없이 제출하고, 코드 울타리 제거 등 형식 정리만 허용한다.
- 같은 문제문·지시문·생성 설정을 새 대화에서 두 번 독립 요청한다. `--round 1/2`는 반복 번호이며 이전 답변이나 채점 결과를 전달하지 않는다. 두 회차 모두 평가하며 수정·추가 질문으로 개선한 결과는 분리한다.
- 유효 정답: AC이면서 실행 시간이 적용 시간 제한 미만인 답변이다.
- 유효 정답률: 유효 정답 수 ÷ 모델당 본 실험 20회입니다. 호출 실패·코드 미생성도 분모에 포함한다.
- 최소 품질 통과선은 원본 유효 정답 12/20회 이상(60%)이다. 일반 AC 비율도 별도로 기록한다.
- 응답 시간은 품질 통과 조건으로 제한하지 않는다. 실행 timeout은 별도의 호출 실패로 기록한다.

## 선정 순서

필수 조건을 충족한 후보 사이에서 다음을 순서대로 비교한다. 앞선 기준이 동률일 때만 다음 기준을 적용한다.

1. 원본 유효 정답률: 높을수록 우선한다.
2. 최소 수정 후 전체 테스트 통과 건수: 많을수록 우선한다.
3. 설명 정확성 평균: 높을수록 우선한다.
4. 전체 모델 응답 시간 평균: 짧을수록 우선한다.

모든 기준이 같으면 동률로 남긴다. 비교에 필요한 기록이나 검토가 미완료면 순위를 확정하지 않는다. 두 후보 모두 60% 미만이면 최소 품질 미충족을 밝히고 상대적 우위와 실제 사용 적합성을 구분한다.

## 최소 수정 보조 평가

양쪽 실패 코드를 같은 기준으로 검토한다. 원래 알고리즘을 유지한 인덱스 ±1, 경계 조건, 초기값 등의 수정이 대상이다. 수정 줄 수만으로 단순 실수라고 판단하지 않으며 핵심 알고리즘 교체는 포함하지 않는다.

직접 수정·재채점하고 원본과 연결된 수정본, 변경 내용, 알고리즘 유지 여부, 전체 테스트 재채점 결과를 별도로 남긴다. 원본 20회의 상태와 수정 대상·실제 수정 시도 수·통과 건수를 함께 표시한다. 호출 실패와 코드 미생성은 수정 통과로 인정하지 않는다. 양쪽 검토·재채점이 덜 끝난 상태로 순위를 확정하지 않는다.

수정본이 통과해도 원본 판정·유효 정답률·60% 통과 여부에는 반영하지 않는다. AI는 원인과 수정 범위를 함께 검토하며 수정본 작성과 실행은 직접 한다.

## 설명 정확성

접근법·정당성·시간/공간 복잡도를 원본 응답에서 확인한다.

| 등급 | 점수 | 판정 기준 |
| --- | --- | --- |
| 정확함 | 2 | 접근법·정당성·시간/공간 복잡도가 정확하고 서로 일치한다. |
| 일부 오류 | 1 | 핵심 풀이의 타당성을 무너뜨리지 않는 일부 오류나 누락이 있다. |
| 핵심 오류 또는 설명 없음 | 0 | 핵심 접근·정당성이 틀리거나 설명이 없다. |

실제 응답 부분에 점수 근거를 연결하고 평균·평가 건수 n·등급별 건수를 기록한다. 정상 수신한 낮은 품질 응답과 코드 미생성 응답도 설명을 평가한다. 호출 실패는 설명 점수에 넣지 않고 별도로 기록한다.

## 발제 집계와 남은 준비

원본 유효 정답률과 별개로 호출 성공 수/전체 시도 수, 지표별 평균과 n, 대표 성공·실패 사례를 유지한다. 미측정 값을 0으로 채우지 않는다.

질문별 기대 결과, 정상·경계·정보 부족/범위 밖 사례, 최종 10문항의 텍스트 적합성, Cloud 공통 5문항 선정과 실제 실행 검증은 남아 있다. 현재 서버 Context는 32768, 본 실험 요청 출력은 30720·reasoning 26624·temperature 0·cache_prompt false로 맞췄다. [기존 reasoning 종료 메시지](reasoning-budget-diagnostic.md)는 유지한다. 이전 설정의 관측과 구분하며 해당 메시지의 결과 기록 보완과 새 설정의 실제 실행 검증은 남아 있다. 워밍업은 호출만 하고 기록하지 않기로 했다. environment 인자와 자동 환경 기록·검증은 제거하고 본 실험의 성능·실패 기록은 유지한다. 실제 서버 적용·VRAM 관측·워밍업 실행과 모델·실행 조건 근거는 별도로 확인한다. 이미 pilot 결과를 본 경과를 밝히고 Cloud 선정 근거를 새 본 실험 전에 고정한다. 이는 결과를 보기 전 선정했다는 의미가 아니다.
